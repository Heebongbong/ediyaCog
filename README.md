# 이디야 선결제 장부

이디야 매장에서 고객별 선결제(충전) 금액을 관리하는 장부 웹앱입니다.
고객이 미리 결제해 둔 금액에서 주문할 때마다 차감하고, 사용 내역을 조회·수정할 수 있습니다.

## 구성

- **프론트엔드**: 정적 파일 3개 (프레임워크·빌드 없음)
  - `index.html` — 화면 마크업
  - `styles.css` — 스타일
  - `app.js` — 로직 (GitHub API, 라우팅, 렌더링)
- **데이터 저장소**: 별도 private GitHub 저장소(`Heebongbong/ediyaData`)의 `data.json`
- **백엔드 없음**: 브라우저에서 GitHub Contents API를 직접 호출해 장부를 읽고 씁니다.

## 주요 기능

- **로그인(서비스 키 게이트)**: GitHub Fine-grained 액세스 토큰(화면에는 "서비스 키"로 표기)을 입력하면 장부를 불러옵니다. 키는 `localStorage`에 저장되어 다음 방문 시 자동 로그인됩니다.
- **고객 목록**: 고객별 남은 잔액과 전체 잔액 합계 표시, 이름 검색 지원. 테이블 헤더(고객명·남은 잔액) 클릭으로 정렬할 수 있습니다.
- **고객 등록**: 목록 화면의 "고객 등록" 버튼으로 이름과 최초 충전 금액을 입력해 신규 고객을 추가합니다.
- **차감·충전 등록**: 고객 상세 화면에서 차감/충전을 토글로 선택하고 내용과 금액을 입력합니다. 잔액보다 큰 금액은 차감할 수 없습니다.
- **사용 내역 조회**: 충전/차감 로그를 시간 역순으로 표시하고, 각 시점의 잔액을 함께 보여줍니다.
- **기록 수정**: 내역에서 로그를 선택해 내용·금액을 수정(종류는 변경 불가). 수정 결과 어느 시점이든 잔액이 음수가 되면 저장을 막습니다.
- **백업·이월 관리**: 헤더의 백업 버튼 드롭다운에서 백업 생성 / 백업 목록 / 로그 이월 정리 / 아카이브 목록을 실행합니다. 생성·이월은 목록 조회 없이 바로 실행됩니다.
  - 백업 생성: 현재 장부를 같은 저장소의 `backups/data_YYYY-MM-DD.json`으로 커밋 (같은 날짜는 덮어씀, 폴더는 첫 백업 때 자동 생성)
  - 백업 목록: `backups/` 폴더의 백업 파일들을 최근 커밋 시각과 함께 나열
  - 로그 이월 정리: 현재 로그 전체를 `archives/logs_YYYY-MM-DD_HHMM.json`으로 보관한 뒤, 각 고객의 로그를 "이월 잔액" 충전 1건으로 압축해 `data.json`을 작게 유지합니다. 아카이브 저장이 성공한 뒤에만 원본을 압축하므로 중간 실패 시 데이터 손실이 없습니다. (Contents API의 파일 1MB 한도 대비)
  - 아카이브 목록: `archives/` 폴더의 이월 파일들을 나열
  - CSV 다운로드: 백업·아카이브 JSON을 브라우저에서 CSV(고객명·날짜·구분·내용·금액·시점 잔액)로 변환해 다운로드 (엑셀 한글 호환 BOM 포함)
- **고객 삭제(소프트 삭제)**: 상세 화면에서 고객을 삭제하면 `deleted` 플래그만 세우고 로그는 보존합니다. 목록·잔액 합계에서 제외되며, 목록 하단 "삭제된 고객 N명 보기"에서 삭제 고객의 잔액·로그 조회와 복구가 가능합니다. 삭제된 고객의 로그는 조회만 됩니다.
- **데이터 갱신**: 장부는 로그인 시 1번만 불러오므로, 다른 기기의 수정 내용은 헤더의 갱신 버튼으로 반영합니다.
- **충돌 감지**: 저장 시 GitHub contents `sha`를 함께 보내, 다른 기기에서 먼저 수정된 경우(409) 로컬 변경을 되돌리고 최신 장부를 다시 불러옵니다. 갱신하지 않은 화면에서 저장해도 덮어쓰기 사고는 나지 않습니다.

## 데이터 구조 (`data.json`)

잔액은 저장하지 않고 항상 로그에서 계산해 파생합니다.

```json
{
  "customers": [
    {
      "id": "c-xxxxxxxx",
      "name": "홍길동",
      "logs": [
        { "id": "l-xxxxxxxx", "type": "charge", "date": "2026-08-01 10:30", "order": "선결제 충전", "amount": 50000 },
        { "id": "l-yyyyyyyy", "type": "deduct", "date": "2026-08-02 14:20", "order": "아이스 아메리카노 2잔", "amount": 6400 }
      ]
    },
    {
      "id": "c-zzzzzzzz",
      "name": "김철수",
      "deleted": true,
      "deletedAt": "2026-08-23 15:00",
      "logs": []
    }
  ]
}
```

- `type`: `charge`(충전, +) / `deduct`(차감, −)
- 잔액 = 로그를 날짜순으로 정렬해 부호를 붙여 합산한 값
- `deleted`/`deletedAt`: 소프트 삭제 표시. 삭제된 고객은 배열에서 제거되지 않고 플래그만 붙으며, 복구 시 두 필드가 제거됩니다. 백업 CSV에는 삭제된 고객도 포함됩니다.

## 라우팅 (해시 기반)

| 해시 | 화면 |
|---|---|
| `#/` | 고객 목록 |
| `#/c/{customerId}` | 고객 상세 (차감·충전 등록, 고객 삭제) |
| `#/c/{customerId}/edit/{logId}` | 로그 수정 |
| `#/deleted` | 삭제된 고객 목록 (로그 조회·복구) |

## 사용 방법

1. GitHub에서 **Fine-grained 개인 액세스 토큰**을 발급합니다.
   - 대상: 데이터 저장소(`Heebongbong/ediyaData`)만 선택
   - 권한: **Contents — Read and write**
2. `index.html`을 브라우저로 열거나 정적 호스팅(GitHub Pages 등)에 배포합니다.
3. 첫 화면에서 토큰을 입력해 로그인하면 장부가 표시됩니다.

## 참고

- 데이터 저장소 위치와 백업·아카이브 폴더는 `app.js`의 `CONFIG` 객체(owner/repo/branch/path/backupDir/archiveDir)에서 변경할 수 있습니다.
- 데이터 저장소 구조: `data.json`(활성 장부) / `backups/`(수동 백업 스냅샷) / `archives/`(이월된 과거 로그 원본)
- 토큰이 브라우저 `localStorage`에 저장되므로 공용 PC에서는 사용 후 반드시 로그아웃하세요.
